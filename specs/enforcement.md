## Supply-chain note: danger.js and pnpm's trust-policy check

Installing `danger` pulls in `@octokit/endpoint@9.0.6` transitively, which trips pnpm 11's built-in `trust-policy: no-downgrade` check (an earlier published version of that package had stronger provenance evidence than this one — a possible supply-chain-takeover signal). This is a real check, reviewed and accepted as a false positive here, not bypassed blindly.

The fix lives in `pnpm-workspace.yaml`'s existing `trustPolicyExclude` list (the project already carries a short list of named exceptions there for the same reason) — `@octokit/endpoint` was added alongside the existing entries. **This setting cannot be set from a project-level `.npmrc`**: pnpm deliberately ignores it from that source so a compromised repo can't quietly weaken its own supply-chain check; `pnpm-workspace.yaml` is the one place the exception is actually honored. Verified: `pnpm install --frozen-lockfile` passes clean with no manual flags needed, for this machine and for CI.
