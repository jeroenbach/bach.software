## Review gate (layer 4): local spec roles, no CI reviewer

The Claude CI review workflow (`claude-code-review.yml`) and the unused `@claude` mention responder (`claude.yml`) were removed deliberately: the spec plugin's roles already carry this layer locally, and they read this file to know what is delegated to the machine.

- **Per story:** `/spec:verify` (qa-verifier) runs the mechanical checks and then judges exactly the review-rubric/judgment-only entries against the story diff.
- **Per feature:** `/spec:audit` (final-reviewer) does the deep whole-branch review with the same delegation rule.
- **Ad hoc:** the local `/code-review` skill for any working diff.

### Judgment-only review rubric

The condensed subset no lint rule, danger check, or CI gate can verify. Reviewers (human or agent) spend their budget here, not on the enforced rows above.

**Frontend (Vue)**

- **Context/presentational split (FE-01..04):** new smart logic (API calls, stores, route reads) belongs in `src/app/contexts/` (`*Context` names); presentational components receive props and emit events only. Flag markup/styling inside a context component, and data fetching inside a presentational one. State lives on the lowest rung that works (component ref before props, before provide/inject, before a store).
- **Component interfaces (FE-02):** props are view-model shaped, never a generated DTO passed through; no callback props (use emits); no boolean soup where one named-state prop fits; child interfaces are exported and extended, not retyped.
- **Naming and placement (FE-04/05):** `Base` only for design-system primitives, general-to-specific word order; shared files singular, never "helper" (single-word component names are already lint-blocked).
- **data-testid coverage (FE-07):** interactive elements, test scopes and asserted values carry ids; reusable components expose `baseDataTestid`; no blanket tagging.
- **Translations (FE-08):** keys name the meaning, not the current English wording; fixed copy is translated by the component that renders it, not passed down as label props.
- **Prop destructuring (FE-11):** a destructure where no destructured prop is used in the script and none has a default should be the bare `defineProps<Props>()` call.
- **Loading Promise Pattern (FE-12):** currently a recorded deviation, but the first feature that introduces a parent-owned async action (child triggers, parent executes) must adopt `createLoadingPromise` instead of passing `isLoading` down. Flag that moment.
- **Storybook states (FE-13):** a new or changed component's stories cover its meaningful states (variants, empty/loading/error, disabled), not just `Default`.
- **Visual regression (FE-14):** a PR with template/CSS changes and a red or absent reg-suit status is not mergeable; the report must be opened before approval.
- **Route queries (FE-17):** link targets and navigations that change one query key spread the whole `route.query` and drop `page` when a filter changes.
- **Backend calls (FE-19):** every generated-client call is wrapped in `useApiState` inside a context; no status-code mapping at call sites (that lives in `useApiErrorReporter` once).

**Backend (C# / API)**

- **Test quality (CS-02):** names follow `MethodName_Scenario_ExpectedBehaviour`; no logic in tests, no shared constructor setup, assert results not mechanisms.
- **Exception handling intent (CS-03):** every catch block recovers, aggregates, compensates, accepts (with a why-comment), or is the top-level handler. Log-and-rethrow and catch-to-return-null are violations.
- **Problem details (API-04):** a new exception type needs a `Classify` arm (derived before base; check the ordering) or it falls to 500; domain rejections use `AppException` with a catalog code, and the 400-vs-422 choice matches the failure class.
- **BFF shape (API-05):** flag projection knobs on queries (`include=`/`fields=`/mode flags), one response contract reused by diverging screens, and per-screen variants of one domain command.
- **Mapping (API-06):** mappers convert shape only. A mapper needing a behavioural test contains logic that belongs in the Application layer.

## Supply-chain note: danger.js and pnpm's trust-policy check

Installing `danger` pulls in `@octokit/endpoint@9.0.6` transitively, which trips pnpm 11's built-in `trust-policy: no-downgrade` check (an earlier published version of that package had stronger provenance evidence than this one — a possible supply-chain-takeover signal). This is a real check, reviewed and accepted as a false positive here, not bypassed blindly.

The fix lives in `pnpm-workspace.yaml`'s existing `trustPolicyExclude` list (the project already carries a short list of named exceptions there for the same reason) — `@octokit/endpoint` was added alongside the existing entries. **This setting cannot be set from a project-level `.npmrc`**: pnpm deliberately ignores it from that source so a compromised repo can't quietly weaken its own supply-chain check; `pnpm-workspace.yaml` is the one place the exception is actually honored. Verified: `pnpm install --frozen-lockfile` passes clean with no manual flags needed, for this machine and for CI. (`@intlify/eslint-plugin-vue-i18n`, added this run, installed clean with no new exception.)
